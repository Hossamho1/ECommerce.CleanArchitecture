### 1. GetPagedProductsQueryValidator.cs
**Location**: `ECommerce.UseCases/Products/Queries/Validators/GetPagedProductsQueryValidator.cs`

Validates:
- PageNumber >= 1
- PageSize between 1-100
- Search term <= 100 characters (if provided)

```csharp
public sealed class GetPagedProductsQueryValidator : AbstractValidator<GetPagedProductsQuery>
{
	public GetPagedProductsQueryValidator()
	{
		RuleFor(x => x.PageNumber).GreaterThanOrEqualTo(1);
		RuleFor(x => x.PageSize).InclusiveBetween(1, 100);
		RuleFor(x => x.Search).MaximumLength(100).When(x => !string.IsNullOrWhiteSpace(x.Search));
	}
}
```

## How It Works: Step-by-Step Flow

### Step 1: HTTP Request Arrives
```
GET /api/products/paged?pageNumber=2&pageSize=15&search=laptop&...
```

### Step 2: Controller Binds Parameters
```
pageNumber=2, pageSize=15, search="laptop", brandId=..., typeId=..., sortBy=..., sortDescending=...
```

### Step 3: MediatR Dispatcher Receives Query
```csharp
new GetPagedProductsQuery(2, 15, "laptop", ...)
```

### Step 4: ValidationBehavior Intercepts
1. Discovers `GetPagedProductsQueryValidator` via DI
2. Runs validation rules (PageNumber >= 1, PageSize 1-100, Search <= 100)
3. If invalid: throws `ValidationException` → Error middleware → 400 Bad Request
4. If valid: calls `next()` → proceeds to handler

### Step 5: Handler Executes (If Validation Passed)

**Sub-step 5a: Count Total Filtered Products**
```csharp
var countSpec = new ProductsListSpecification(
	search: "laptop",           // Filters
	brandId: guid,
	typeId: null,
	sortBy: ProductSortField.Name,
	sortDescending: false,
	skip: null,                 // ← NO PAGINATION
	take: null
);

var totalCount = await repository.CountAsync(countSpec);
// SpecificationEvaluator.GetCountQuery() applies WHERE + INCLUDE but NOT Skip/Take
// EF Core: SELECT COUNT(*) FROM Products WHERE ...
// Result: 247 (total matching products)
```

**Sub-step 5b: Fetch Paginated Items**
```csharp
var skip = (2 - 1) * 15;  // = 15

var pagedSpec = new ProductsListSpecification(
	search: "laptop",
	brandId: guid,
	typeId: null,
	sortBy: ProductSortField.Name,
	sortDescending: false,
	skip: 15,               // ← DATABASE OFFSET
	take: 15                // ← DATABASE FETCH NEXT
);

var products = await repository.ListAsync(pagedSpec);
// SpecificationEvaluator.GetQuery() applies WHERE + INCLUDE + OrderBy + Skip + Take
// EF Core: SELECT ... FROM Products WHERE ... ORDER BY ... OFFSET 15 ROWS FETCH NEXT 15 ROWS ONLY
// Result: 15 Product entities (items 16-30)
```

**Sub-step 5c: Map to DTOs**
```csharp
var dto = products.Adapt<IReadOnlyList<GetAllProductResponse>>();
// Mapster transforms: Product → GetAllProductResponse
```

**Sub-step 5d: Create PagedResult**
```csharp
var paged = new PagedResult<GetAllProductResponse>(
	Items: [15 DTOs],
	TotalCount: 247
);

return Result<PagedResult<GetAllProductResponse>>.Success(paged);
```

### Step 6: Controller Handles Result
```csharp
var paged = result.Value;  // PagedResult with 15 items and totalCount=247

var pagination = new PaginationMeta(
	pageNumber: 2,
	pageSize: 15,
	totalCount: 247
);
// Calculates:
// - TotalPages = ceil(247/15) = 17
// - HasPreviousPage = 2 > 1 = true
// - HasNextPage = 2 < 17 = true

return Success(paged.Items, null, pagination);
```

### Step 7: HTTP Response Sent
```json
{
  "success": true,
  "data": [
	{ "id": "...", "name": "Gaming Laptop Pro", "price": 1299.99, ... },
	... 14 more products ...
  ],
  "meta": {
	"traceId": "...",
	"pagination": {
	  "pageNumber": 2,
	  "pageSize": 15,
	  "totalCount": 247,
	  "totalPages": 17,
	  "hasPreviousPage": true,
	  "hasNextPage": true
	}
  }
}
```

public sealed class BrandsListSpecification : Specification<ProductBrand>

		int? take = null)

	}
}

## Support & Troubleshooting

### Validation Fails with 400 Bad Request
- Check PageNumber >= 1
- Check PageSize between 1-100
- Check Search term <= 100 characters
- See ValidationBehavior logs for detailed errors

### No Products Returned But TotalCount > 0
- Check database has products matching filters
- Check search term (case-sensitive in some databases)
- Check brandId/typeId GUIDs exist
- Run SQL manually to verify results

### TotalCount Wrong (Off By One)
- Ensure count spec has `skip: null, take: null`
- Ensure paged spec has skip and take values
- Check SpecificationEvaluator.GetCountQuery() not applying Skip/Take

### Performance Degradation
- Add SQL indexes on filtered columns (Name, ProductBrandId, ProductTypeId)
- Limit PageSize maximum (currently 100, consider 50)
- Add query result caching for popular filters
